# 予定・体育館・配車の差分修正（2026-09-06）

## データ互換性
- 部活予定のフォームは日程・予定名・色・メモに限定。既存の時間、venueId、courts、通知等は編集時に消さない。
- 体育館割当は `venueAssignments[eventId] = {venueId}` に保存する。未割当は従来の event.venueId を参照。期間予定は既存の1予定という単位を維持する。
- 練習メニューの保存済みコンテキストは変更しない。既存の「反映」操作で新しい割当・出欠を取得する。計算、種目、セット、履歴のロジックは変更しない。
- 幹部予定は events の1レコードをやること一覧にも投影する。tasks にコピーしない。既存tasksは期限として幹部カレンダーに投影する。既存の別々の予定・タスクを推測で統合・削除しない。
- 幹部予定の完了は元のeventに記録する。予定編集者は編集可能、担当者は完了のみ。空の担当者リストは幹部全員。サーバーが完了者を確定する。
- 出欠の手動値、初期値、配車の履歴・単価・往復・確定済み精算は既存処理を維持。

## UI
- 部活と幹部のカレンダー切替、複数日・曜日・期間・シリーズ編集・画像を維持。
- 体育館先選択→日程チェック→一括適用。他体育館から変更するときだけ確認。
- 配車は運転者見出しを横に並べる直接編集。人数上限は運転者込み4人。名前全体の450ms長押しと、名前→移動先のタップに対応。
- 未配車は編集画面のみ赤系で表示。画像は日付・体育館・運転者・同乗者・区分のみ。
- 備品を維持。会計は追加しない。体育館取りは準備中の入口のみ。

## 検証
- Pythonの保存APIテスト：体育館関連データの保存・GET、旧予定と練習データ保持、同日同時刻の複数幹部予定、二重保存なし、権限、通知ジョブ。
- EdgeドメインとPostgres APIスモーク：同じ関係データ・完了・保存再読み込み・不正参照・権限を検証。
- JS：既存の練習計算200パターン比較、出欠、4人上限、交代、往復/片道、精算、カレンダー。追加で配車コピー照合、練習コンテキスト参照、投影、長押し/スクロール/キャンセル、画像の未配車除外。
- 390×844ブラウザー：部活フォーム4項目、幹部予定保存→再読み込み→やること表示、体育館2日一括保存→再読み込み、運転者交代→再読み込み→同乗者保持、画像プレビュー。

## 残課題・検証範囲
- Supabase本番は既存の `push:false` を維持。通知候補は保存できる。Python版の通知ジョブ生成を回帰検証したが、実プッシュ送信の有効化や外部への試験送信は行っていない。
- 実機iOS/Androidでの長押し感触は未確認。ジェスチャーの自動テストとデスクトップブラウザーでのタップ経路を検証。

## 追記：日程ドラッグと配車メニュー
- カレンダー上の予定名、または予定が1件だけの日の450ms長押しで日程を移動する。長押し成立前の10px超の移動は通常スクロールとしてキャンセル。複数日選択は既存ボタンを維持する。
- 移動は元レコードのdate/endDateを変更し、出欠・体育館割当・練習履歴のID参照を保つ。期間の長さと時刻は保ち、シリーズは動かした1件だけを分離する。
- 配車がある予定では配車権限も確認し、標準の往復利用日をずらして下書きに戻す。配置と単価は保持する。精算ロック中は移動しない。
- 配車ヘッダーに日付・体育館、完了、メニューを配置。コピー・設定・表・画像はメニュー内へ集約。
- スマホ幅でメニュー、設定保存と再読込、画像プレビューを確認。日程移動・期間・重複・権限・ロック・ジェスチャーのタイミングを自動テスト。実機タッチ操作は未検証。
