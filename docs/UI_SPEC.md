## 2. デザイントークン

以下は実装基準値。CSS変数へ集約する。

```css
:root {
  --bg: #ffffff;
  --surface: #f6f7f6;
  --text: #18211c;
  --muted: #717a74;
  --line: #e5e9e6;
  --green: #14813b;
  --green-soft: #edf7f0;
  --red: #c73535;
  --red-soft: #fff0f0;
  --radius: 6px;
  --input-h: 44px;
  --row-h: 56px;
  --header-h: 56px;
  --nav-h: 64px;
  --gutter: 18px;
}
```

- フォントは `-apple-system, BlinkMacSystemFont, "Hiragino Sans", "Noto Sans JP", "Noto Sans CJK JP", "Yu Gothic", sans-serif`。本番でフォントを配布する必要がなければOS標準を使う。
- 本文15px、補助12～13px、画面タイトル20～22px、区切り見出し16px。入力欄は16pxを基準。
- 一覧は白地＋1px区切り線。影は原則なし。画面全体の背景グラデーション禁止。
- 主ボタン44～48px高、角丸6px、緑単色。補助ボタンは文字か細枠。
- アイコンは単色線画SVGで統一。絵文字や人物アバターの装飾は不要。
- タップ領域44pxを基本。配車の狭い名前行は表示をコンパクトにしつつ操作対象の高さを確保。
- エラーは赤とテキストを併用。未選択・不参加を緑の強調にしない。
- 名前は原則1行。重複姓だけ区別できる表示名にする。全文は選択時に確認可。
- セーフエリア、ソフトキーボード、360/390/430px幅を考慮する。

## 3. 共通シェル

通常画面は上部ヘッダー＋内容＋下部タブ。下部は「ホーム／予定／やること／運営／設定」。ラベルは11px前後、アイコン22px、選択中だけ緑。プラスボタンは右上の44pxタップ領域内に置き、意味のない浮遊アクションを複数置かない。

戻るは上部左、タイトルは左寄せまたは中央のどちらかを全画面で統一。詳細・フォームには戻る。編集フォームは上部右に「保存」、投稿だけ「投稿」、配車完成は「登録」。通常の一覧で「保存済み」を常時出さない。

初期グループ名はデータから表示し、画像にあった「東大バスケットボール部」を本番の固定名にしない。デモは「〇〇大学バドミントン部」。日付曜日は日時データから計算し、2025年の画像サンプルを固定しない。

## 5. 配車編集の具体配置

390px幅で内容の左右余白12px、列間8px、利用幅366pxを目安に `grid-template-columns: minmax(0, 2fr) minmax(112px, 1fr)`。狭幅360pxでも右パネルの名前と学年が読めること。左の車幅を無理に詰める代わりに、名前を縦一列で表示する。人物アバターは不要。

上部は3段以内。

1. 戻る／配車／登録
2. `9/12（土） 市民体育館`
3. `往復` または `行き｜帰り` と、コピー／表のコンパクトな操作

左パネルは `大学配車`、車カード、`＋ 車`、`駅配車`、車カード、`＋ 車`。未使用区分は空の追加領域だけでよい。車カードの運転者行は太字＋小さなハンドルアイコン。同乗者は3行まで。満員なのに空ドロップ欄を表示しない。

右パネルは `未配車 2`（赤）、`3年`、名前、`2年`、名前、下に `配車不要`、学年別。配車不要は折りたたみ可能。「メンバー／未配置」という意味が重なるタブは削除する。必要な未配置者は全員同じ規則で赤くし、画像のように任意の1人だけを赤くしない。

ドラッグ中は対象枠を淡い緑で強調し、元の項目を残像にする。ドロップで移動完了、キャンセルで元へ。ドラッグしていないときに巨大な点線枠と「ここにドロップ」を繰り返し表示しない。空欄は「＋」または「運転者」の最小ラベルだけ。

### 運転者の変更例

右の中島 → 池田カードの運転者欄 → 見出しが中島に変わる。既存同乗者は残る。池田は右の元の必要区分へ戻る。配車必要者なら赤くなる。

車の順序と運転者名は別管理。運転者が変わっても車の位置・同乗者が全部リセットされない。

## 6. 配車表の具体寸法

- タイトル18～22px相当。日付、体育館、往復／片道だけ。
- 区分見出し14px。
- 一列の最小幅128～156px。ヘッダー48px、同乗者行44～48px。
- 3人の同乗者がいれば3行。全車が2人以下なら無用な4・5行目を作らない。
- 一番上は運転者名だけ。名前を二度表示しない。
- 行背景は白。列境界は1px。運転者ヘッダーは薄緑。
- 項目が増えてもフォントを極端に小さくしない。画面では横スクロール。書き出しではスクロール領域全体。
- 大学／駅のグループ別に表を分けてよい。所属の色分けはしない。
- 保存画像には編集ボタン、コピー、人数警告、ナビゲーションを含めない。

## 7. 画像から再現しないもの

| 生成画像の要素 | 実装時の扱い |
|---|---|
| 東大バスケットボール部 | データのグループ名へ。デモはバドミントン部 |
| 2025年の日付と曜日の不整合 | Date/Intlで生成 |
| 自分タブの他人だけのタスク | 表示しない |
| 部活のみで幹部会が混在 | 表示しない |
| 予定画面の選択タブが運営 | 予定を選択 |
| 配車が下部タブへ昇格 | 運営のまま |
| 1台目・2台目 | 表も編集も運転者名主体 |
| 同じ人の重複・誤った4/4 | データから計算・検証 |
| ドライバー一括チェック画面 | 最新仕様では廃止 |
| シャトルの単位「本」 | 入力された単位。デモは筒 |
| 募集中・締切などの状態ラベル乱立 | 下書き／登録を内部管理、必要時だけ表示 |
| 毎列の車アイコン＋運転ラベル | 共有表では削除 |
| 往復と行きと帰りの3表を同時集計 | 正規化して二重計上禁止 |

## 8. レスポンシブ・検証

390×844を基準にし、360×800、430×932、768×1024、1280×800で確認。通常画面はスマホで1列、PCで最大幅を抑えたアプリ表示。配車編集だけ広い画面では作業幅を広げてよいが、右の名簿は約1/3を維持。

配車以外の一覧は縦スクロール。カレンダー画像プレビューと配車表のみ横スクロール可。入力時に保存ボタンをキーボードに隠さない。固定フッターで最後の行を覆わない。

実装担当は主要5画面＋配車編集＋配車表のスクリーンショットを出し、HTML参照と並べて確認する。文字・人数・担当・日付が正しいかは画像比較とは別にテストする。
